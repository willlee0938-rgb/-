# DriveOS — 中古車 AI 銷售營運工作台

目前版本：V4 模組建置中（靜態前端 + 可選 Supabase 登入／雲端資料庫）
使用者定位：遠端中古車合作銷售窗口，以 Facebook 社團 / Threads 免費流量獲客，合作車行負責現場賞車、專業說明、簽約與交車。

## 立即執行
建議從儲存庫目錄啟動本機靜態伺服器：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

使用瀏覽器開啟此本機服務，首頁為「審核與發布工作台」。儲存庫已附可直接發布的 `assets/cloud.js` 與 `assets/publishing.js`；執行網站不需安裝套件。所有 HTML、JS、CSS 和 assets 目錄須一起發布，不能只下載 index.html。

`config.js` 沒有雲端連線資訊時，保留本機示範模式；設定 Supabase 後，先登入才讀取該帳號的資料。新帳號不會自動帶入示範或本機客戶。

**啟用雲端請閱讀 [白話設定步驟](SUPABASE_SETUP.md)。** 程式與 SQL 已實作；實際 Supabase 專案須由使用者開通及驗證。

## 登入與雲端儲存

- Supabase 電子郵件／密碼登入、登出、忘記密碼與重設密碼。
- PostgreSQL 每帳號一個工作台，RLS 限制只能讀寫自己的資料。
- 版本條件更新，避免另一個裝置用舊資料覆寫；衝突時保留草稿，下載備份後選擇載入雲端。
- 寫入失敗會保留本機草稿並顯示狀態，重新整理後可以重試。
- 舊本機資料由使用者確認後搬入空白帳號，不自動推定歸屬。
- 工作台文字與照片關聯上限 7MB；照片檔獨立存於 Supabase 私人圖庫，不占這個 JSONB 上限。尚無多人共用工作台。

連線設定只能放 Project URL 及公開 Publishable／anon key，不能放 secret、service_role 或資料庫密碼。資料隔離由資料庫 RLS 執行，不依賴隱藏前端畫面。

## 車源匯入

支援 CSV UTF-8 和 JSON，先預覽新增、更新、不變、錯誤，再確認寫入。來源名稱＋車源編號為唯一鍵，更新保留車輛 ID 和客戶／貼文關聯。

不覆蓋 CRM 或轉介，不刪除檔案未出現的車。重複編號、無效資料或預覽後庫存改變會擋下整批寫入；售出或改價會撤銷文案核准與提醒。

範本：[CSV](sample-inventory.csv)、[JSON](sample-inventory.json)。尚未自動抓取或連接凱爾車源。

## 審核與發布工作台

首頁選車 → 準備雙平台文案 → 修改文案、選照片、勾選社團或 Threads 帳號 → 核准並加入發布清單。車源卡片的「準備廣告」可直接帶入該車。文案目前依已知車源資料套版，尚未接 AI。

「發布位置」保存社團首頁或 Threads 個人頁網址，每篇廣告可選多個位置，各自保存任務。相同文案與位置重複加入不會重複建立。逐站複製文案、下載照片與文案 ZIP、開啟平台，最後填入該位置的實際貼文網址。網站只記錄使用者提供的結果，不會驗證平台貼文存在、可見或已獲社團管理員核准。尚未串接平台發布 API、帳號授權或背景排程；預定時間僅顯示台北時間的待辦，關閉網站不會推播或發布。

車價、庫存、文案及照片改變後，未完成任務暫停，需重建或重新審核並加入清單；已完成任務保留當時文案。取消與移除位置保留歷史。位置放在 `settings.publicationTargets`，逐站任務放在 `posts[].deliveries`，沿用每帳號的工作台同步、RLS 與 JSON 備份，不需新增 SQL。原媒合中心可繼續用於客戶轉介與佣金。

ZIP 在瀏覽器產生，只包含本次勾選的照片、文案與發布說明。私人照片經目前登入帳號下載，不把簽名網址寫進工作台；單張上限 10MB、照片總量 50MB，有一張失敗就不產生缺圖的 ZIP。外部圖片需要來源允許跨站讀取，失敗時請改上傳雲端圖庫。五台範例模式獨立存在記憶體，重整清除，不更動正式庫存、不開啟發布平台、不記錄成真實發布；範例 ZIP 使用有示範標示的插畫與文案。

## 車輛照片管理

在車源卡片點「照片管理」，可一次上傳多張 JPG／PNG／WebP、選封面與移除照片。原始檔每張上限 25MB；瀏覽器上傳前自動縮至最長邊 1600px，視檔案調整 JPEG 品質，一般以 500KB 內為目標，處理後硬性上限仍為 5MB。小於目標且尺寸足夠的小圖保留原檔，不為了轉格式反而增大。每次最多 10 張，每車最多 20 張，HEIC 請先轉 JPG。雲端帳號需要額外執行 [圖庫設定檔](supabase/photos.sql)，已有圖庫不需要重跑。

縮圖保持比例、不裁切；轉成 JPEG 時透明部分合成白底。原始高畫質檔請自行保留，圖庫僅保存實際上傳的版本。照片大小、原始大小和尺寸記錄在工作台，顯示用的短效網址不寫入資料庫。

照片管理顯示「已連結照片」的容量估算，按帳號與物件路徑去重；外部網址、未連結檔案及其他資料不列入，缺少大小的舊照片會標示未知。可自行設定工作台照片容量提醒門檻（MB），達 80% 顯示提示。這不是 Supabase 總用量，也不會改變方案或自動阻止上傳；實際配額與流量仍看 Supabase Usage。

照片放在私人 bucket `driveos-vehicle-photos`，路徑為帳號／車源／隨機檔名；帳號只能上傳、讀取與刪除自己的照片。資料庫只保存 `storagePath` 等中繼資料，短效簽名網址只保留在記憶體，用於顯示。匯入的外部圖片仍保留原 HTTPS 網址。

更換封面或照片會撤銷原廣告核准。移除雲端照片時，先確認資料庫關聯已儲存，才清理未被其他車引用的檔案；同步失敗會保留檔案及草稿。若檔案上傳後網路或清理失敗，可能有未連結的檔案留在圖庫，需於 Supabase Storage 檢查；目前沒有自動垃圾回收。

JSON 備份不包含照片檔，只包含位置；還原私人照片需要相同 Supabase 專案與帳號，已刪除的原檔不能靠 JSON 還原。圖庫容量依 Supabase 方案限制，建議事先縮小照片並保留原檔。

業務流程與正式自動化待辦見 [BROKER_WORKFLOW.md](BROKER_WORKFLOW.md)。

## 5 組廣告範例

網站左側「廣告範例」，或直接開啟 `?view=examples`，可比較 Altis、Fit、Mazda3、RAV4、X3 的示範車卡，以及各自的 Facebook 社團／Threads 文案。五組均標示虛構測試數值與非真實庫存，不代表凱爾報價或市場行情。

資料在 ad-examples.js，頁面在 ad-examples-ui.js；使用現有示意插畫，沒有下載實車照片。切換、預覽及複製範例不會寫入工作台或覆蓋雲端車源。文案為預先準備的套版，非 AI 串接，也不會自動發布。

## 遠端媒合中心
- 可售車批次產生 Facebook 社團／Threads 套版文案，保留人工審核。
- 同一車源與平台避免重複建立進行中的草稿。
- 台北時區的發布提醒，設定間隔與每目的地每日提醒上限。
- 車源、價格、文案或平台變動後撤銷核准與提醒；車源變動需重建文案。
- 客戶與車源關聯、凱爾接待窗口、賞車時間及可複製的轉介摘要。
- 記錄車行回報，區分預計佣金、確認佣金與已入帳金額。

目前排程為工作台內的提醒紀錄，沒有背景通知或自動發文。手動發布後須填寫實際平台貼文網址；示範車源不可記錄為真實發布。尚未連接 AI、車行資料來源、平台 API 或後端排程服務。

## 驗證

開發使用 Node.js 24，套件版本鎖在 package-lock.json：

```sh
npm ci
npm run build
npm test
```

修改 cloud-entry.js／cloud-sync.cjs 後需重建並提交 assets/cloud.js。GitHub Pages 從 main 根目錄直接發布已提交檔案，不執行 npm 建置。

測試包含業務流程、150 台車匯入、儲存失敗／衝突，以及 PGlite PostgreSQL 引擎上的 RLS、匿名拒絕與版本更新。環境有 Python Playwright 與 Chromium 時，啟動本機服務後執行：

```sh
python3 tests/browser-smoke.py
python3 tests/publishing-browser.py
python3 tests/cloud-browser.py
```

第一支驗證 11 個頁面、媒合流程及五組雙平台廣告範例；第二支驗證多位置審核、照片選擇、ZIP 內容、發布證明網址、改價失效與手機畫面。最後一支使用 Supabase API 測試替身驗證登入、帳號隔離、匯入、私人照片 ZIP、發布任務同步、跨裝置、失敗草稿、舊資料搬移與衝突。測試替身不能取代真實 Supabase 專案驗證；正式服務仍需確認實際登入、跨裝置與重設密碼。

瀏覽器驗證：產生草稿 → 核准 → 安排提醒 → 修改車價確認撤銷；建立轉介 → 記錄車行成交及確認佣金 → 確認入帳。以獨立瀏覽器測試，避免污染實際資料。

## 重要現況
- 現在所有車源均為示範資料，不是真實車行庫存。
- 雲端未設定時，資料仍只存在瀏覽器；啟用後每個帳號以獨立 JSONB 工作台保存，尚無多人共用或即時合併修改。
- 尚未串接合作車行網站 / API。
- 文案目前為已知車源資料套版，尚未串接 AI 服務。
- 尚未具備 Meta / Threads 發布功能。

## 原則
- 車況、事故、保固、貸款、價格等不得由 AI 捏造。
- 車行資料只在取得合法授權後同步。
- 自動發布只能使用平台官方允許且帳號已授權的方式。
- 不使用繞過平台限制、違反社團規範或大量洗版的自動化。
